# 个人工作台

基于需求 v0.9（保留产线 FR-19～FR-25 增量）与根目录 `prototype/` 最新方案 A 的正式工程。单用户、本机浏览器与后台；业务数据保存在独立的 SQLite 数据目录。没有预置任务、虚构同步结果或模型回复。

## 在 Windows 启动

使用 Node.js 24 和 npm，在项目根目录运行：

```powershell
npm ci
npm run build
$env:WORKBENCH_DATA_DIR = 'D:\project\personalwork-codex-data'
npm start
```

浏览器打开 `http://127.0.0.1:4310`。停止后台可按 Ctrl+C。关闭浏览器不会删除已保存的数据，后台停止期间不执行同步或提醒。

默认数据目录为 `%LOCALAPPDATA%\PersonalWorkbench`。首次启动建立空数据库和两处未启用的来源设置。设置中可查看实际数据、产物目录及保护快照状态。不要将数据库放在网络共享盘，也不要把真实凭据放进仓库或提示词。

**当前电脑使用上面显式指定的仓库外目录。** 默认 LOCALAPPDATA 目录在本环境对同目录新文件 rename 返回 EXDEV，保护快照无法保存，底层原因尚未确定；原目录已保留。`D:\project\personalwork-codex-data` 已实测创建、重命名、替换、回读及启动保护快照成功。每次启动须保留此环境变量，避免打开另一份独立空库；其他电脑可按实际环境换用自己的专用目录。

可用的非敏感环境变量：

| 变量 | 用途 |
| --- | --- |
| `WORKBENCH_DATA_DIR` | 独立业务数据目录，建议专用本机目录 |
| `WORKBENCH_OUTPUT_DIR` | AI 文件产物根目录，默认数据目录下 artifacts |
| `WORKBENCH_PORT` | 后台端口，默认 4310 |
| `WORKBENCH_HOST` | 默认 127.0.0.1；远程绑定需额外安全配置 |
| `WORKBENCH_ORIGIN` | 浏览器使用的准确 Origin，须与 Host 一致 |

开发运行：`npm run dev`。Vite 为开发服务，生产使用上面的 build/start。

## 功能与边界

- 今日工作台：今日要事、待办／进行中、等待反馈、临期／超期、产线高风险／受阻、待评审MR和今日完成；桌面双列、窄屏单列。
- 任务中心：统一以列表查看研发、人员、招聘、交办及周期生成任务；支持安排今日、状态切换、父子任务、等待／阻塞、排序和归档。永久删除需二次确认，清除当前数据库中的任务及相关操作历史，保留子任务并解除关联；历史回顾快照、既有备份和导出副本仍保留，来源再次同步或周期重新生成可能带回任务。详情使用“任务描述”，隐藏项目／专题、预期结果、结果与验证输入，存量字段继续保留；保存成功直接关闭，失败保留输入。个人行动和来源状态仍分别记录。
- 任务日历：月／周视图按周一起始，展示个人计划、本地硬截止和跟进日期；同一任务同一天合并标签，可定位日期、前后切换、回到今天、筛选日期类型及显示已完成／已取消。归档任务不显示，未设置日期的任务在任务中心安排。点击任务复用详情编辑器，保存后共用同一条任务；窄屏月视图显示日期与数量，点击日期查看下方完整清单，周视图按日期排列。只提供任务日期视图。
- 管理看板：最多三条使用中的产线，总览卡片展示本月完成率、周进展四状态及分级开放风险，点击进入单线详情。月重点有完成度和备注；按月／周切换、上周对比、遗留标识及一键批量结转，重复操作复用目标记录。风险有等级、目标闭环日期和升级标识，高等级／逾期未闭环在首页及管理页标红，支持产线／等级组合筛选。月完成率按已完成数／非取消数统计，周完成不自动完成月目标。原有风险转问题、专题里程碑和周期规则继续保留。
- 产线周期管理：每线默认周五站内提醒，可在编辑产线时设置周几；新周／月提示初始化。月末当天看实时完成率，结束后自动保存汇总；后台关闭时不运行或推送，启动后按状态历史补算已结束月份（包括空月份），缺失历史标为待复核。页面每分钟刷新，月末记录不因次月变化重写。
- 回顾：周／月自动勾选本期事项，可手动增减；报告按1、2、连续编号，每项一行“1、任务标题--状态”，完成只写完成，进行中／未完成可补简短原因。新建时默认勾选“下周计划”，按回顾结束日期之后的下一自然周，自动选择计划日期在该周的未完成事项；可增减或关闭，计划单独从1编号。支持编辑、复制、Markdown 导出及交付版本。历史回顾可在二次确认后整体删除，包括全部交付版本，关联任务和管理事项保留；删除无法直接撤销，既有备份／导出副本不受影响。旧章节式回顾继续可读写；人员／招聘资料与敏感关联默认排除。
- 提示词：新增、编辑、搜索、原文复制、未保存保护；失败保留输入。
- 来源：PingCode 与 GitLab 独立设置、真实 HTTP 适配器、主动／定时同步、身份去重、本地绑定及跨来源关联。GitLab 同步指派给我的 Issue、MR 和由我评审的 MR，去重后进入任务中心；未关闭事项不限历史天数，MR 保留版本变化与待复查。
- PingCode：固定目标评论预览、明确提交、操作标记去重和来源核实。**状态覆盖因原子条件写能力尚未核实而阻止提交**，不能视为状态回写验收通过。GitLab 始终只读。
- 模型：本地 OpenAI 兼容／Ollama、DeepSeek、New API 多套配置；文本与工具闭环分别验证。DeepSeek 不接收内部材料，未知上游不接收内部材料，无自动服务切换。
- AI：可编辑拆解与总结、单次计划授权、资料读取、真实 Markdown 文件保存与回读、限定 PingCode 评论提交／核实；预算、取消、部分结果及中断待核实。未开放通用 shell、工程修改或 GitLab 写操作。
- 数据：事务、修订冲突保护、Windows DPAPI 包裹密钥、加密凭据、口令加密备份、本机保护快照及恢复前副本。

真实地址、凭据及模型由用户在设置中输入。连接测试不会通过写入公司资料来试权限。已保存配置、认证读取、模型文字能力、工具能力及业务验收是不同状态。

提示词数据库保存原始正文；系统剪贴板使用平台行尾约定，Windows 下读回为 CRLF，保留字符、缩进与空行。

## 备份与迁移

在“设置 → 备份与恢复”导出口令加密 `.pwb` 文件，口令至少 12 字符并另行保管。备份包括任务、提示词、管理、来源快照、模型非敏感配置、执行记录、关联及历史；不包含访问凭据、主密钥和文件产物本体。备份明文 JSON 上限 30 MiB，超过时明确失败。产物目录需要单独备份。

后台启动及每小时更新当日保护快照，保留最近七个快照日，恢复前副本另行保留。保护快照只能在原机器／账号及对应主密钥下解密；同盘快照不能抵御磁盘损坏。可移植备份使用独立口令，适合迁移。

恢复会替换业务数据并重新生成修订号；首先校验内容和关联、保留当前数据保护副本。同步、模型调用或执行在途时拒绝恢复。恢复后来源和模型停用、凭据需重新输入、能力需重测，外部写入与执行记录转为阻止／待核实，不能自动续跑。Windows 的 DPAPI 文件不能直接作为 Linux 密钥使用。

Linux 服务、TLS 与迁移说明见 [部署说明](docs/implementation/部署说明.md)。这份部署配置尚未在公司 Linux 服务器实测。

## 检查和证据

```powershell
npm run check
npm run test:e2e
npm run test:restart
```

`check` 顺序执行类型、lint、单元／本地 HTTP 集成、生产构建。E2E 使用独立随机测试数据目录；重启检查运行真正的独立后台进程及 SQLite，只创建 synthetic 数据。若默认4310端口已有工作台在运行，可设置 `$env:WORKBENCH_E2E_PORT = '4311'` 后运行 E2E，测试不会复用或停止现有服务。

新周回顾自动附加独立的“产线进展”节，包括本周重点、受阻／有风险项及本期风险新增／闭环；该节创建后可编辑，复制、Markdown导出和交付版本保留保存时的快照。普通汇总及周报排除递归敏感关联。更新程序后，已运行的后台须按原数据目录重启，再刷新浏览器以加载新增接口；没有自动替换或迁移真实数据。

[需求与验收追溯](docs/implementation/需求追溯.md)、[验证记录](docs/implementation/验证记录.md)明确区分代码实现、本地检查和外部环境验收。公司 PingCode、GitLab、三类真实模型、Linux 实机均须在相应环境另行验收；本地 HTTP 夹具通过不能替代这些结论。

## 代码组织

| 目录 | 职责 |
| --- | --- |
| `apps/web/src/pages` | 今日、任务中心、任务日历、管理、回顾、提示词、执行及设置页面 |
| `apps/web/src/components` | 编辑器、AI 辅助、表单与共用组件 |
| `apps/server/src` | HTTP、安全、持久化、管理、来源、模型、执行与备份 |
| `packages/contracts/src` | 前后台共用数据类型和运行时校验 |
| `tests` | SQLite、真实 loopback HTTP、保护边界、浏览器回归 |
| `docs/implementation` | 方案、分阶段计划、追溯、验证与部署 |
| `prototype` | 只读参考输入，未纳入正式页面 |

没有配置远程仓库，没有发布到公司服务器。
