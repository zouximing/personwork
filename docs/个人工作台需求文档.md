# 个人工作台需求文档

版本：v0.10

日期：2026-11-07  

## 1. 产品定位与工作分类

个人工作台服务于每天的工作安排、执行、跟进和回顾。重点做好两件事：推进本人承担的任务，以及掌握三个产线的月周重点进展和风险。

### 1.1 核心业务入口

| 入口 | 包含内容 | 建设重点 |
| --- | --- | --- |
| 任务中心 | 研发、Bug、平台提效、AI 基建、人员沟通、招聘、经理交办、中心总结、周期生成任务及 PingCode／GitLab 来源任务 | 以行动清单统一查看和操作，支持任务描述、个人安排、状态、跟进、父子任务与删除 |
| 管理看板 | 三个产线的月周重点、进展、风险、专题里程碑及周期规则 | 掌握产线目标、阶段进展、偏差和风险，维护周期任务规则并关联任务中心的行动 |

任务展示与管理规则：

- 研发、人员、招聘、交办、中心周月总结等行动统一进入任务中心；日常工作和管理协作作为任务属性保留。
- 管理看板不设置“其他管理事项”分组；人员、招聘和交办使用任务中心的共用任务机制，以类型区分。
- 周期规则在管理看板维护，已生成及新生成的各期任务均在任务中心跟进。

部门平台提效与 AI 基建在任务中心跟进行动，并通过专题里程碑关联目标和风险。MR 评审位于任务中心的专项视图，评审状态和版本信息按需展开。

研发来源任务主要从公司内网部署的 PingCode 拉取，保留任务编号；MR 合并请求评审从公司内网部署的 GitLab 拉取，保留所属项目及 MR 编号。来源任务进入任务中心后补充个人安排与跟进，无需重复录入。本地可补充临时和管理协作事项；GitLab MR 不要求已有 PingCode 任务编号。

### 1.2 产品重点

本人执行的功能实现、Bug 修改、平台提效，以及三个产线的重点进展是首版核心。AI 辅助、任务执行和提示词库作为共用能力服务于这两个方向。

首页呈现个人今日重点，同时让产线本周偏差和高风险直接可见；具体布局在原型阶段确认，按事项紧急程度、计划和本人选择安排展示。

### 1.3 工作场景与归属

| 工作内容 | 归属 | 呈现方式 |
| --- | --- | --- |
| 软件功能实现、Bug 修改 | 任务中心 | 按任务类型查看和安排个人行动 |
| GitLab MR 评审 | 任务中心 → MR 评审 | 从内网 GitLab 拉取，可关联 PingCode 任务 |
| 部门平台提效、AI 基建 | 任务中心与管理看板专题里程碑 | 行动在任务中心跟进，专题目标、里程碑和风险在管理看板关联 |
| 三个产线的月周重点、风险跟踪 | 管理看板 | 查看目标、阶段进展和风险，引用任务中心的关联行动 |
| 人员沟通、招聘、经理协同与中心周月总结 | 任务中心 | 共用任务列表、状态和跟进机制，不建设独立人事或招聘系统 |
| 固定周期事项 | 管理看板维护规则，任务中心跟进任务 | 每期生成独立任务，同期重复生成复用已有任务 |

这些场景用于说明覆盖范围，不再对应多个并列功能模块。

## 2. 核心目标与首版范围

### 2.1 核心目标

1. **知道今天先做什么。** 个人任务有重点、有下一步，临时插单后可以调整安排。
2. **知道产线重点推进到哪里。** 月目标与周阶段结果能关联，对照计划查看实际进展。
3. **知道哪些事项需要介入。** 等待反馈、进展偏差、阻塞及风险能够及时进入关注范围。
4. **减少重复整理。** 日常进展与结果可用于个人回顾及中心周月总结。
5. **保持使用轻便。** 小任务快速记，重点事项按需补充，普通管理事项不引入复杂流程。

### 2.2 首版范围

| 能力 | 首版做到什么 |
| --- | --- |
| 今日工作台 | 个人今日重点、待处理和待跟进事项，以及产线本周偏差与关键风险 |
| 来源设置 | 分别配置 PingCode 与 GitLab 的内网地址、认证、项目／拉取范围及同步规则，保存配置、测试连接并查看结果 |
| 任务中心 | 统一管理研发、人员、招聘、交办及周期生成任务；行动清单按列表显示，支持安排今日、状态切换及二次确认永久删除；来源与个人安排分别保留 |
| 任务日历 | 使用月／周视图查看个人任务和管理任务的计划、本地硬截止与跟进日期，支持日期筛选、定位和任务详情编辑，与任务中心共用记录 |
| 产线管理 | 三个产线的月重点、周重点、负责人反馈、偏差、协调动作、风险与结转 |
| 周期事项 | 在管理看板维护规则和收集要求，每期独立生成任务并进入任务中心，支持等待与跟进 |
| AI 辅助与任务执行 | 拆解任务、生成总结，并通过已接入工具执行授权范围内的具体行动；有执行计划、过程、产物和核验结果 |
| 模型接入 | 支持本地部署模型、DeepSeek 官方 API、New API 网关，保存多套配置，按实际能力选择文本生成或任务执行 |
| 常用提示词库 | 新建、编辑、保存、查找并复制提示词正文；下次打开继续使用，可选填入 AI 指令 |
| 回顾与数据 | 周月材料整理、人工编辑与导出、可靠保存、备份恢复，以及同步／回写结果追踪 |

人员、招聘、平台提效使用共用任务机制。MR 专项视图位于任务中心；AI 操作融入任务、执行记录与回顾；提示词库是共用工具入口。完整代码评审操作在公司 GitLab 中进行。

首版必须覆盖两处来源接入、PingCode 受控回写、MR 变化跟进、提示词库、三类模型接入及真实 AI 任务执行；本地录入、手工总结和模型生成文字不能代替相应接入或执行验收。GitLab 保持只读，不在工作台发布意见、批准或合并 MR。

“高级同步或自动化”包括定时拉取、变化识别、回写结果跟踪、安全重试与冲突处理；AI 按明确的任务类型调用已注册工具完成执行。具体周期、回写字段、执行场景和授权范围须评审后确定；未定义的跨系统自动操作不作为无限范围承诺。模型、工具、数据许可或写权限未就绪时，应标明对应能力未验收。

### 2.3 后续再考虑

- 超出首版字段清单的 PingCode 批量写入、工时／附件处理和复杂跨系统业务自动化，具体按后续场景评估。
- 自动代码评审、行级讨论及复杂 MR 分析视图。
- 人员／招聘等正式决策、未授权的跨系统操作，以及真实仪器控制、烧录、量产或生产发布。
- 独立会议／预约日程、任务时间块、重复日程、外部日历同步、投入时间观察和更灵活的周期任务。
- 跨设备同步、多人协作、离开工作台后的消息提醒。
- 只有实际使用证明必要，才扩展更细的人员或招聘流程。

## 3. 页面与日常使用

### 3.1 简化信息架构

左侧导航名称统一为四个汉字，依次为“今日工作、任务中心、快速捕获、任务日历、管理看板、工作回顾、提示词库、执行记录、系统设置”。页面标题可使用完整名称。

| 入口 | 主要内容 |
| --- | --- |
| 今日工作 | 个人今日重点、待跟进；三个产线需关注的周重点偏差与风险 |
| 任务中心 | 汇集个人任务、管理协作与周期生成任务，行动清单按紧凑列表显示标题、任务描述、优先级、个人行动状态和计划日期，提供安排今日、状态切换和永久删除快捷操作；保留 PingCode 与 GitLab 来源、项目、编号、来源状态和最近同步时间，支持编号搜索及来源／项目／类型／优先级／个人行动状态组合筛选，可按优先级从高到低排序，同优先级按个人排序排列 |
| 快速捕获 | 快速记录临时事项并整理收件箱 |
| 任务日历 | 按月／周查看任务的个人计划、本地硬截止和跟进日期，定位日期、切换周期、回到今天，点击任务查看和编辑同一条记录 |
| 管理看板 | 展示产线月周重点、进展、风险与专题里程碑，维护周期规则；关联行动及各期生成任务在任务中心跟进 |
| 工作回顾 | 周月回顾自动勾选本期事项，生成可编辑的编号简报；默认包含可选的下周计划，支持复制、导出及 AI 辅助草稿 |
| 提示词库 | 查看、搜索、新建、编辑、保存与复制个人常用提示词 |
| 执行记录 | 查看所关联任务、执行计划、授权范围、运行状态、工具操作、产物及核验结果，可从任务详情进入 |
| 系统设置 | 来源与同步、模型配置、工具权限、备份及分类；分别维护 PingCode、GitLab 的连接与同步规则、凭据和连接测试 |

收件箱作为待整理分组，可通过快速捕获或任务中心进入。MR 视图位于任务中心，按待审、评审中、等待修改、待复查、已结束筛选，突出新提交、本人未处理行动及来源时效。

### 3.2 日常使用方式

- **开始工作：** 查看或刷新 PingCode 任务及 GitLab 待审／待复查 MR，选个人今日重点，查看产线周重点异常和当天待跟进事项。
- **安排日期：** 在任务日历中查看本月／本周的计划、截止和跟进分布；选择日期查看完整任务清单，打开任务详情调整日期。未设置日期的任务在任务中心安排日期后进入日历。
- **工作中：** 快速记新事项，复制常用提示词，按需让 AI 提出建议或在授权后执行任务；核对产物与结果，选择需要回写 PingCode 的内容；需要他人反馈时安排跟进。
- **结束工作：** 补充结果、阻塞和下一步，调整未完成事项。
- **每周：** 查看三个产线周重点结果、对应月目标的推进情况，以及下一周安排。
- **每月：** 回顾月重点交付、延期和风险，安排下月重点；按需要整理中心总结。

具体检查时间和频率待确认，不强制建立新的会议或填报制度。

### 3.3 今日工作台（TW-01～TW-09）

首页采用 React/Fastify/SQLite，沿用会话及 CSRF 鉴权，工作域为个人任务与管理。日期按 Asia/Shanghai 计算，并显示对应星期。

| 编号 | 需求与验收口径 |
| --- | --- |
| TW-01 | 默认首页标题“今日工作台”，显示日期和星期及每日开工引导。首页分区由一次 GET /api/dashboard 聚合，依次为提醒、四张概览、今日要事、待办／进行中、等待／临期超期、产线告警／待评审 MR、今日完成；桌面双列、窄屏单列，各区有空态。保留来源同步状态与设置入口。 |
| TW-02 | 待办仅取未归档 todo 且 startDate 为空或不晚于今日；截止升序、空值靠后，同日高优先级在前。进行中取 doing；等待取 waiting 并按 followUpDate 升序。临期／超期仅取 todo/doing/waiting，硬截止今天或早于今天；超期在前。计划日期 planDate、开始日期 startDate、硬截止 dueDate、等待预期回复／跟进日期 followUpDate 分别保存。 |
| TW-03 | 每日最多三件未结束要事，以独立 keyDate 表达，保留既有 focus 专注字段；完成、取消、归档不占配额。跨日自动不再入选，不删除历史事件；过期日期不限制重开与备份，今天及未来日期仍分别最多三件，备份以生成时的上海日期校验有效配额。仅当前 keyDate 不能重建完整历史快照。后端事务限制上限，普通新增／PATCH 同样不可绕过；满三件返回400。收件箱设要事自动转todo。支持选择、单件设置、完成、开始、移出；选择器包括已选等待任务以便移出，新增候选为todo/doing/inbox。批量保存携带当前及新选择修订，冲突409且整批回滚。 |
| TW-04 | 等待任务展示等待对象、内容、预期回复日期及逾期。催办弹窗提供可编辑文案与复制，失败提供手工复制；不对外发送。waiting 三项必填沿用后端校验。任务首次进入done由后台记录completedAt；重开清空当前完成时间、保留事件；再完成重新计时。今日完成只读倒序，按上海当日区间统计，旧记录缺时间时仅从完成事件恢复，不以updatedAt猜测。 |
| TW-05 | 收件箱、opened待评审MR、产线告警条数、今日完成四张概览分别显示未整理、积压、风险、完成。前三张跳对应收件箱筛选、MR页签、产线看板，完成卡无跳转。MR只取本人评审职责的opened记录，已评审且无需复查不计待评审；停留按本地首次见到createdAt至当前的完整24小时计算，明确不是GitLab原始创建时长。列表最多10条，积压优先，阈值默认2天。 |
| TW-06 | 产线告警复用风险登记册与本周周重点：未闭环高等级或目标闭环日早于今日的风险、at_risk/blocked周重点，排除归档产线与取消重点；一风险涉及多线按产线各列一条。显示级别、负责人、超期／升级、目标日期和最新进展，点击进入对应产线详情。 |
| TW-07 | 提醒实时计算不落库，包含task_overdue、task_near_due、waiting_overdue、key_empty、mr_backlog、interview、line_weekly_update、line_monthly_init。按danger/warning/info排序，同一目标合并展示、保留各命中原因。面试复用脱敏recruitment任务followUpDate，今天至明天（含），结束任务不提醒；不新建候选人系统。每周更新提醒在配置星期当天对未填actual的有效周重点触发；每月25号起，本月有月重点但下月未登记时提醒，跳产线详情并提供既有结转操作。 |
| TW-08 | 首页展示非info提醒，顶栏铃铛显示全部提醒、角标最多9，每60秒请求GET /api/reminders，可跳对应事项。设置支持截止提前量（默认1天）、周更新日（默认周五，ISO 1～7）、MR积压天数（默认2）、浏览器通知（默认关闭）。仅用户开启时请求通知权限；danger通知去重、只含通用提示，不带任务／人员正文；拒绝权限不影响应用提醒，不承诺浏览器关闭后送达。设置纳入备份与恢复。 |
| TW-09 | Ctrl+Alt+N在任意已登录页面打开现有快速记录；首页“快速记录”和侧栏“快速捕获”导航提供入口，侧栏不显示录入框或捕获按钮。/capture独立页提供标题Enter入库，默认personal/inbox，支持连续逐条捕获并列出收件箱供整理。保留未保存保护、失败输入和重复提交保护；10秒是操作目标，不作为未经计时的性能结论。 |

新增字段采用向后兼容默认值；已有来源状态、计划日期、专注与历史回顾正文继续保留，深墨绿导航延续。P01/P02/P05/P09、S01及AC01/AC02/AC05/AC07由TW编号补充追溯。

### 3.4 任务日历

任务日历是任务的日期视图，覆盖个人任务和管理任务，与任务中心共用同一条任务记录、状态和日期。

| 项目 | 需求 |
| --- | --- |
| 导航与默认视图 | 左侧提供“任务日历”入口，默认打开当前日期所在月份并选中今天，突出显示今天和选中日期。 |
| 月视图 | 按自然月展示，周一至周日排列，补齐月初、月末所在的完整周；相邻月份日期与当前月份区分。桌面月格预览前三项任务，超出时显示剩余数量，并提供查看当日完整清单的入口。 |
| 周视图 | 按周一至周日展示选中日期所在周，每天展示全部符合筛选条件的任务；显示实际起止日期，跨月、跨年仍保持完整自然周。 |
| 日期定位 | 支持指定日期、上／下月、上／下周和回到今天。月末切换到较短月份时选中该月最后一天，正确处理大小月、闰日及跨年。 |
| 日期类型 | 展示个人计划日期、本地硬截止日期和下次跟进／检查日期，分别使用“计划”“截止”“跟进”标签。来源系统的截止日期独立保留，不自动作为本地硬截止进入日历。 |
| 同日合并 | 同一任务的多种日期落在同一天时，只显示一项任务并合并对应标签；落在不同日期时分别展示。同一任务在本月／本周的任务总数中只计一次。 |
| 日期筛选 | 三种日期类型默认全部选中，可独立勾选；只展示选中类型对应的日期和标签。全部取消时提示至少选择一种日期类型，无匹配任务时显示空态。 |
| 状态与范围 | 默认展示未归档、未完成且未取消的任务；可勾选“显示已完成／已取消”，结束任务保留状态标识。归档任务始终不显示，未设置任何日期的任务保留在任务中心。 |
| 排序与逾期 | 同一天内优先显示高优先级任务，同优先级按个人排序排列；未结束任务的本地硬截止早于今天时显示逾期提示。 |
| 任务查看与编辑 | 点击任务打开共用任务详情，保存成功后日历和任务中心立即显示一致内容，重新打开仍能读取。改期保留原任务身份和关联；调整已有本地硬截止需填写原因，保存修订冲突或失败时保留输入，离开未保存内容时提供保护。 |
| 窄屏显示 | 月视图显示日期与任务数量，点击日期后在下方展示完整任务清单；周视图按日期排列。标题和日期标签可读，页面无横向溢出。 |
| 时间与边界 | 今日日期按 Asia/Shanghai 计算，日期与具体时刻分开处理。日历只提供任务日期视图，独立日程、具体时段、重复日程、外部日历同步和日历专属系统推送不属于首版范围。 |

## 4. 共用任务规则

### 4.1 分类与关联

主分类保留“个人任务”或“管理”，作为任务属性使用，两类任务统一展示在任务中心。分类按事项的主要目的确定，执行人另行记录：本人写中心总结属于管理，本人修复产线 Bug 属于个人任务；分类不决定任务是否进入任务中心。

同一任务只保存一份，可关联产线、项目、专题、人员或周期重点。在任务中心、今日工作台、任务日历和产线重点中展示同一事项时，共享任务身份、进展与结果，汇总不重复计数。

产线工作与本人行动可以关联但不混为一谈。例如“产线完成联调”由产线负责人推进，“本人协调测试资源”是关联的管理行动；协调完成不等于联调完成。

### 4.2 最少录入内容

| 场景 | 需要的信息 |
| --- | --- |
| 快速记录 | 只填标题即可保存，默认收件箱状态、中优先级；可选择高／中／低优先级及个人行动状态，选择等待反馈或阻塞时补齐对应跟进信息 |
| PingCode 来源任务 | 任务编号、来源身份与项目、标题、原始页面链接、来源状态和最近成功同步时间；负责人、优先级、截止等按权限和实际字段获取 |
| GitLab 来源评审 | 来源实例、项目、MR 编号、标题、作者、评审相关人员、原始页面链接、MR 状态、当前提交版本和最近成功同步时间；字段以实际权限和版本为准 |
| 普通任务整理 | 主分类、优先级、个人行动状态、任务描述；日期、类型、执行人和允许编辑的关联对象按需填写 |
| 等待反馈 | 等待谁、等待什么、下次跟进日期 |
| 阻塞 | 阻塞原因、解除动作或求助对象、下次检查日期 |
| 产线重点 | 所属产线与周期、预期结果、负责人、计划节点、实际进展及反馈时间 |

计划处理日期、硬截止日期、对方承诺日期、下次跟进日期分别表达，不自动互相替代。无截止日期的任务也能正常使用。

任务详情以“任务描述”作为行动内容的字段名称，不显示“项目 / 专题”“预期结果”“结果与验证”三个输入区域。已有对应数据继续兼容保存，修改其他字段不得将其清空；来源项目、专题里程碑、产线目标及执行核验保留各自的信息与入口。

点击保存并成功后立即关闭任务详情，返回原列表或视图并显示已保存内容；保存失败或修订冲突时保留详情和输入，明确提示错误，未保存离开时提供保护。

### 4.3 优先级、状态与记录

本地任务与个人行动的优先级统一为高、中、低，默认中。已有任务或旧备份缺少优先级时按中处理，保留原任务身份、状态和关联。

- 快速记录与任务详情均可选择优先级和个人行动状态；优先级与状态分别保存，单独修改其中一项不重置另一项。
- 任务中心列表和今日任务同时展示优先级与个人行动状态；任务中心支持按两项组合筛选，并提供高、中、低顺序的优先级排序，同优先级按个人排序排列。
- 任务优先级与个人行动状态保存后，刷新、重新打开和备份恢复应保持一致。保存失败保留输入，未保存离开时提供保护。
- 窄屏任务列表的筛选项换行排列，优先级与状态标签保持可读，无横向溢出。

本地任务与个人行动使用共用状态：收件箱、待处理、进行中、等待反馈、阻塞、已完成、已取消。PingCode 原始工作流状态、GitLab MR 外部状态和本人评审进展分别展示，不强制改成这套状态；个人行动结束不等于来源任务结束，MR 已合并也不等于本人已完成评审。

- 选择等待反馈时填写等待对象、等待内容和下次跟进日期；选择阻塞时填写阻塞原因、解除动作或求助对象、下次检查日期，信息不完整时不得保存为对应状态。
- 延期和逾期是日期提示，不增加另一套任务状态；调整截止日期保留原值和原因。
- 个人行动完成、验证通过、最终交付分别表达，不能把“代码修改完成”直接视为“已验证交付”。
- 已取消不计为完成成果；完成任务重开时保留原完成事实与重开记录。
- 重要结果、负责人反馈、计划变更保留发生时间、记录内容和必要来源；任务永久删除时按第4.11节清除该任务的当前记录及操作历史。
- 归档收起历史记录，保留检索和关联；未完成事项归档时需明确后续安排。
- 首版以工作台内提示为主，完成或取消后停止行动提醒，不承诺关闭工作台后送达提醒。

### 4.4 PingCode 双向同步与个人安排

以下为基于用户已明确来源补充的候选规则；接入方式、拉取范围和刷新节奏仍待确认。

| 信息范围 | 内容与维护边界 |
| --- | --- |
| PingCode 来源信息 | 编号、标题、项目、原始状态，以及可读取的负责人、优先级、截止等；拉取更新来源快照，经确认的字段支持回写，不整条覆盖来源记录 |
| 工作台个人安排 | 本地优先级、个人行动状态、今日重点、个人计划日期、个人排序、任务描述、跟进日期、备注和产线／周期关联；由本人维护，与来源优先级和来源状态分别保存，来源刷新不得覆盖 |
| 来源与同步信息 | 来源组织／实例、项目及工作项身份、最后成功时间、拉取／回写结果、变更前后记录；用于识别来源、判断时效和核对结果 |

- 列表、详情、搜索和总结引用保留 PingCode 任务编号，并能打开原始页面；任务编号与工作台自身编号不能混淆。
- 去重优先采用来源组织／实例与工作项内部 ID 的组合，任务编号用于展示和查找。只有编号而尚未解析身份时，结合来源与项目进行核实，不跨组织仅凭编号或标题合并任务。
- 同一工作项重复拉取只更新同一记录；本地临时任务后续对应到 PingCode 时，经本人确认建立关联并保留已有记录，不再维护副本。
- 拉取范围建议先限本人负责及主动选定关注的事项；是否包含本人创建、参与或已完成任务，以及历史范围，后续确认，不默认拉取全组织资料。
- 首版支持主动刷新与可配置的定时拉取，实际频率待确认，不预设实时更新；显示进行中、成功或失败及最后成功时间，允许暂停定时同步。
- 外部断连、权限不足或部分数据未返回时，保留已保存信息和个人安排，明确标记状态；不能将“本次未拉到”视为已删除或已完成。
- 来源负责人变化、已确认归档／删除或移出拉取范围时，提示本人处理本地计划，保留已有历史与周期引用；不静默删除，不继续把旧快照展示为当前事实。
- 来源状态保留原名，未知状态不猜测映射；如需归并为待办／完成，须核实实际工作流后配置。本人结束一次行动不能自动把 PingCode 任务计为交付完成；来源关闭后也需检查剩余个人行动。
- 仅拉取工作所需字段；正文、自定义字段、附件及评论不默认全部复制。访问凭据不进入任务正文、普通备份或日志。

首版回写规则：

- 双向指“来源更新可读入，工作台选定变更可写回”，不代表每个本地字段都与来源自动互相覆盖。今日重点、个人计划、私人备注、产线周期关系默认只在工作台保存。
- 建议首批回写能力为任务状态更新和本人选定的进展评论；优先级、截止日期等是否纳入，以字段清单评审和本地版本验证为准。私密备注不自动当作评论发布。
- 回写前展示目标项目、任务编号、原值与新值或评论正文，由本人发起提交，或由已批准执行计划内的受限工具提交；实际允许字段与状态流转以来源权限和工作流为准。任务授权需覆盖目标、操作、字段和数据范围，不能只凭字段清单让 AI 自行改写。
- 写入前检查来源是否已有变更；有冲突时展示来源现值与本地建议，不采用默认“最后写入覆盖”。技术设计必须验证实际接口的并发保护能力，不能把单次先读后写宣称为无并发风险。
- 回写区分草稿／待提交、提交中、已确认成功、失败、结果待核实和冲突。收到成功响应后核对来源结果，再更新本地快照；失败不伪造来源状态，也不清除本地草稿。
- 超时或响应丢失时先核实来源再决定重试，避免重复状态变更或重复评论；重复点击同一次提交应保持单次效果。离线可保存草稿，重新连通后重新检查来源，不默认将过期草稿直接发出。
- 自动重试仅针对能够安全确认未生效或具备去重保障的操作，并可停止；不把不确定写入无限重发。记录提交人、目标、时间、变更范围和结果，不记录凭据。
- 双向回写纳入首版验收；若某必要字段缺少写权限、工作流不允许或接口无法提供可验证的保护措施，应明确该项限制及未验收状态，不静默降级为只读后宣称完成。

### 4.5 GitLab MR 拉取与评审跟进

- 来源已明确为公司内网本地部署的 GitLab。按确认的项目及本人评审职责拉取 MR，支持主动刷新及可配置的定时拉取；频率与提醒节奏待确认。
- 评审范围建议包含指派本人评审及本人主动选定关注的 MR；评审人、作者和 MR 负责人需要区分，不能仅筛选本人创建的 MR 来代替待审列表。实际分配规则与部署版本支持情况待核实。
- 列表显示来源项目、MR 编号、标题、作者、外部状态及最近同步时间，可打开内网原始页面；当前提交版本用于识别本人评审针对的内容。
- 本人评审进展至少区分待审、评审中、等待作者修改、待复查和已结束，并记录结论、未解决事项、已检查的提交版本与下一步。等待作者修改时安排跟进。
- 新拉取版本与本人已检查版本不一致时，保留原结论及其版本，提示重新复查；不能把旧版本结论直接沿用为当前版本已审。
- 同一实例、项目和 MR 身份重复拉取仅更新同一记录；不同项目的相同 MR 展示编号不得误合并。MR 与 PingCode 任务是不同来源对象，可建立关联但不合成同一条来源记录。
- 一项 PingCode 任务可以关联多个 MR，一个 MR 也可能服务多个事项；没有明确关系时允许暂不关联，不依赖标题相似自动绑定。汇总时区分代码评审行动与业务交付成果，避免重复计算。
- MR 合并、关闭、撤回评审安排或来源不可访问时，提示本人检查遗留计划；不自动标本人已评审，不静默丢弃备注、历史结论或产线周期引用。
- GitLab 与 PingCode 独立显示同步结果和最后成功时间；其中一处失败不影响另一处刷新及已保存的个人安排。无访问权限时如实提示，不绕过权限或把缺失记录当成已完成。
- MR 专项视图至少显示待审、评审中、等待作者修改、待复查与已结束，支持按项目、作者、更新时间筛选，并突出新提交与需复查原因；位于任务中心内。
- 首版只读取管理评审所需的 MR 元信息，不默认复制仓库源码、完整差异或全部讨论，不自动发表意见、批准或合并。

### 4.6 公司内网接入约束

两处数据源均为公司内网本地部署，这是已确认前提；工作台本身采用桌面应用还是公司内网网页仍待确定。

- 工作台负责拉取数据的运行端必须能通过公司允许的网络路径访问两处内网服务，原始链接也应在授权网络环境下打开；不默认它们可被公网服务直接访问。
- 不以申请公网暴露、配置外网转发或上传至第三方同步服务作为默认方案；如有特殊需求，再单独确认范围和授权。
- 接入前分别核实实际版本、接口可用性、组织／项目范围、本人身份映射、GitLab 读取权限、PingCode 读取及字段写入权限，以及内网域名解析、代理和证书信任要求。不能因公开文档存在某字段，就认定本地版本支持。
- 内网连接失败与登录／权限失败分别提示；内网证书问题按公司允许的信任方案处理，不默认跳过证书校验。
- 两处访问凭据独立管理，不写入任务、普通备份或日志；缓存、备注和导出仍属于公司内部资料。工作台部署与备份位置需符合公司制度，不因来源位于内网就默认允许向外传输。

### 4.7 AI 辅助与任务执行

AI 既可以提供拆解和总结，也可以通过工作台已接入的工具执行具体任务。模型负责理解与规划，执行器按权限调用工具，工作台记录过程并核验结果；只返回一段“已完成”的文字不算实际执行。

| 场景 | 输出或实际行动 | 使用方式 |
| --- | --- | --- |
| 任务拆解 | 建议子任务、预期结果／验收点、依赖和待澄清内容 | 编辑、选择后加入本地任务；如需向来源系统写入，进入单独授权流程 |
| 周月总结 | 依据所选事实生成“编号、任务标题--状态”简报，完成只写完成，进行中／未完成可附简短原因；下周计划独立编号 | 保留来源，区分本期事实与未来计划，人工复核后复制或导出 |
| 查询与整理执行 | 读取授权范围内的任务／MR、汇集资料、建立本地跟进记录或生成并保存文件 | 在已批准的数据、工具和输出位置范围内执行，展示真实工具结果与产物 |
| PingCode 行动执行 | 通过允许的接口更新状态或发布选定进展 | 复用回写校验、冲突处理和结果核实；执行计划明确目标、操作与字段 |
| 本地项目执行（待确认场景） | 可能涉及读取工程、修改文件、运行脚本或测试 | 需确认是否纳入首版具体场景及允许工作区／命令，未确认时不默认开放通用命令执行 |

前两项需求明确；任务执行也是首版必需能力。表中执行用例为候选，需选定至少一个真实工具闭环作为首版验收场景；首批执行用例待明确，不能把全部候选视为默认操作权限。

执行规则：

- 发起任务时选择目标、关联任务、模型配置和允许材料，展示计划、拟用工具、可能写入的位置及成功条件。
- 可按单次任务授权明确的工具、项目、字段、目录和预算；已授权范围内连续执行，无须每一步重复确认。出现新增目标、越权操作或超出原授权的数据范围时暂停并说明原因。
- 工具必须预先注册并具有明确参数与返回结果；工作台校验目标、参数及权限，拒绝未知工具或不合规参数。模型回复本身不能获得新的工具权限。
- 状态至少区分待启动、计划中、待授权、执行中、已暂停、已完成、失败、部分完成、已取消和结果待核实；记录步骤、模型配置、调用结果、必要产物引用及核验结论。
- 成功条件基于实际工具回执、可读取的产物或预设检查；无法验证时标记待核实。过程和核验结果供本人复核，不直接作为正式验收证据。
- 支持停止后续步骤和查看部分结果；已发出的外部写入可能已经生效，需核实，不承诺取消即可撤销全部影响。重试复用回写去重和冲突机制。
- 来源正文、提示词引用材料和模型输出不构成额外授权，不得让其中的指令改变权限、切换到未许可模型或自行触发外部动作。
- GitLab 在本版仍只读，AI 不能发表意见、批准或合并；人员／录用正式决策、真实仪器控制、烧录、量产和生产发布不在执行范围。
- 模型、工具或内网服务不可用时，保留草稿、执行记录与已确认结果；人工工作仍可使用。占位回复、模拟接口或只有计划没有工具操作，不算任务执行验收通过。

### 4.8 模型与服务配置

首版支持以下三类接入；服务类型与具体模型分别配置，不固定某个模型版本。

| 接入类型 | 需要支持的配置 | 验证重点 |
| --- | --- | --- |
| 本地部署模型 | 公司或本人允许使用的模型服务地址、协议／适配方式、模型标识及实际需要的认证 | 从运行端实际连通并生成结果，确认上下文与工具调用能力；不假定所有本地模型支持同一接口 |
| DeepSeek 官方服务 | 官方 API 接入、API 凭据、模型标识及调用参数 | 通过官方 API 验证认证和调用；不采用官网网页自动操作或保存网页登录密码，API 权限与费用另行确认 |
| New API 部署 | 网关地址、网关令牌、网关提供的模型名称或别名及路由要求 | 验证实际网关版本、转发模型和工具调用兼容性，确认最终上游及数据流向 |

- 可保存多套有名称的连接配置，选择默认配置，并按任务选择或切换；本地部署的 New API 网关不代表最终模型也在本地，需记录实际路由和数据许可。
- 每套配置包括服务类型、地址、协议适配、模型、凭据引用、超时和必要参数；认证信息独立保护，不写入提示词、任务正文、普通备份或日志。
- 提供连接检查和实际模型调用检查，区分网络、认证、模型不可用、额度／限流和协议不兼容；返回错误时不显示为连接成功。
- 文本生成、结构化输出、工具调用等按实际测试记录能力。接入成功不代表工具执行能力也可用；不支持所需能力的模型不能被选为该执行任务的后端。
- 对需要工具调用的任务，验证模型提出调用、执行器执行、工具结果回传、后续结果生成这一完整闭环；不要仅根据模型名称或接口格式宣称兼容。
- AI 请求发起前可查看模型配置及选入材料范围；公司内网数据仅进入许可服务，默认排除人员／候选人敏感记录、私人备注、密钥、患者数据和未脱敏日志。
- 不因某服务失败而静默改投另一模型，尤其不自动从本地切换到外网。切换需满足原数据许可；执行中不静默改变模型、权限或预算，必要时暂停确认。
- 输入长度、调用次数、超时、执行步数与费用预算可设约束；实际服务不能提供的用量或费用信息标为未知或估算，不伪造精确数值。
- 三类接入均需用真实服务、虚构／脱敏材料验证；至少一个通过能力检测的模型完成代表性任务执行，其余配置按已测能力展示，不能把不支持工具的配置标成可执行。
- 所有生成内容保留使用的配置、时间与必要来源；事实、推断、建议分别表达，缺少证据时标待确认。

### 4.9 常用提示词库

目标是保存本人经常使用的提示词，编辑并保存后，下次打开能够直接复制使用；无需先连接或调用模型。

- 每条至少包含标题和正文，可选用途／标签；支持新建、查看、编辑、明确保存和按标题或正文搜索。
- 编辑保存后更新原记录并记录更新时间，重新打开读取最近成功保存的内容；未保存修改有清晰提示，保存失败保留输入。
- 提供复制正文入口，保留多行、缩进、特殊字符及占位符原文，不自动附带标题、格式包装或执行指令。
- 复制成功后给出反馈；剪贴板访问失败时明确提示并允许手工选择复制，不误报成功，也不因点击复制调用模型或执行任务。
- 提示词可用于外部工具；也可选择填入工作台 AI 指令，仍需单独选择模型、材料和执行授权。复制或使用提示词不自动覆盖原文。
- 提示词库随完整数据备份与恢复保存，模板中不存真实 API 密钥或账号密码；内容如含内部信息，按相同资料边界保护。

### 4.10 PingCode 与 GitLab 设置

两处来源均须提供可编辑、保存并重复使用的设置入口，内网地址、身份与项目不能写死在程序中。首版每类至少支持一套独立配置，不要求用户修改代码或配置文件才能连接自己的服务。

| 设置范围 | PingCode | GitLab |
| --- | --- | --- |
| 连接与身份 | 配置名称、内网服务地址、实际部署支持的认证方式与访问凭据；测试后显示可识别的当前账号／组织信息 | 配置名称、内网服务地址、实际部署支持的认证方式与访问凭据；测试后显示可识别的当前账号 |
| 拉取范围 | 组织／项目、本人负责或主动关注等筛选、历史范围；具体选项以实际接口为准 | 项目、本人评审或主动关注的 MR、状态及历史范围；具体选项以实际接口为准 |
| 同步规则 | 主动刷新、定时拉取开关和周期；工作流映射、允许回写字段与回写启用状态 | 主动刷新、定时拉取开关和周期；评审身份匹配、相关筛选，保持只读 |

- 支持查看、编辑、保存和停用配置；重启后保留最近保存的非敏感设置和受保护的凭据引用。必填缺失、地址格式错误或同步参数无效时给出具体提示，不清空已填内容。
- 连接测试使用当前编辑内容，明确标记“未保存配置的测试”或对应已保存版本；仅验证网络、认证及必要的读取能力，显示通过／失败、测试时间与可确认的身份。结果不足以确认写权限时明确标为未验证，不自动发表评论或修改任务来试写。
- 保存成功、读取测试通过、回写权限验证和同步启用分别表达。保存不代表连接成功，也不自动启动回写；读取通过不能认定 PingCode 已具备写权限，GitLab 设置中不开放写操作。
- 凭据默认遮蔽，编辑空值表示保留原凭据，清除或更换使用明确操作；禁止普通导出和日志记录明文。认证方式按实际部署适配，不要求在需求评审或聊天中提供真实凭据。
- 地址或凭据变更后，原连接结果标为需重测；不将原凭据自动发送到新地址。项目／范围变化需说明新增或移出的范围，已有记录与个人安排保留，不将未再拉到的任务删除。
- 核实地址修改属于同一实例地址调整还是切换新实例；新实例采用独立来源身份，不能仅靠任务／MR 展示编号合并。旧实例的待提交回写保留原目标并暂停，禁止随配置变更转写到新实例。
- 停用后停止新发起的定时拉取和回写，保留历史、关联及个人记录；已发出的请求继续按结果待核实规则处理。恢复启用需使用已保存且有效的配置。
- 超时、代理或内网证书信任等环境设置按需要放在高级项，不影响基本地址／凭据／项目的填写；不默认跳过证书校验。

### 4.11 任务中心列表、快捷操作与永久删除

任务中心提供行动清单、MR 评审与来源关联视图。行动清单使用列表，每行展示标题、任务描述、优先级、个人行动状态、计划日期和快捷操作；支持打开详情、既有筛选、排序及归档查看，桌面与窄屏均应清楚呈现任务和操作。

- **安排今日：** 将个人计划日期设为今天；收件箱任务同时转为待处理，其他未结束任务保留当前状态。已完成或已取消任务须先重开，再安排今日；不修改来源截止日期和来源状态。
- **状态操作：** 在列表直接切换个人行动状态，进入等待反馈或阻塞时收集第4.2节规定的信息，缺失时不得提交。操作失败或修订冲突时保留任务及已填内容并提示错误；不将个人状态变化自动写到来源系统。
- **未保存保护：** 列表快捷操作及其返回结果不得清除另一任务详情的未保存标记，也不得用迟到的列表结果覆盖较新的任务内容。
- **删除确认：** 点击删除后显示二次确认，明确任务标题、永久删除范围及无法直接撤销。取消或关闭确认窗口不删除；确认提交期间阻止重复操作，成功后移除列表及当前详情中的已删任务，刷新或重启后仍不出现。
- **删除范围：** 清除当前数据库中的任务、任务操作历史及活引用，不保留回收站、删除审计或任务占位记录。子任务保留并解除父任务关联；产线周期重点、风险、里程碑、来源绑定及自动创建标记、周期生成记录、回顾当前选材与下周计划选择、执行授权范围中的任务引用均须清理。相关待授权执行计划取消，其他业务记录保留。
- **一致性与失败：** 删除校验任务修订号，并将任务及关联清理作为完整事务保存。修订冲突、保存失败或关联清理失败时不删除任何部分，保留任务、确认窗口及错误提示；同步、模型调用或任务执行在途时拒绝删除。
- **历史副本：** 删除任务不改写已保存的历史回顾正文、事实快照、交付版本及既有备份、导出和执行产物副本。历史材料继续可追溯，允许引用已删除任务的事实快照；回顾本身的删除按第7节规则处理。
- **重新出现与隐私：** 恢复删除前的备份、来源再次同步或显式重新生成同一周期，可能重新带回任务，确认提示应说明此边界。删除任务或重新绑定来源不得解除存活材料原有的敏感标记、分享限制及内部上下文的数据许可约束。

## 5. 任务中心需求

任务中心是个人行动的统一入口，集中跟进研发、Bug、平台提效、AI 基建、人员沟通、招聘、交办、中心总结及各期周期任务。内网 PingCode 与 GitLab 来源任务共用个人安排机制，来源身份与原始状态独立保留；管理看板保留目标、进展、风险和周期规则。

| 编号 | 需求 |
| --- | --- |
| P01 | 在任务中心统一整理 PingCode 任务、GitLab MR、本地个人与管理协作任务、已有及新增周期任务，支持来源编号／标题搜索和来源、项目／专题、类型、优先级、个人行动状态组合筛选；本地补充只填标题即可进入收件箱并使用中优先级，快速记录和任务详情可选择优先级及个人行动状态，等待反馈和阻塞按共用规则补齐信息。 |
| P02 | 维护高／中／低本地优先级、个人行动状态、今日重点、个人计划日期与排序，可按优先级从高到低排列，同优先级按个人排序排列；任务中心和今日任务展示优先级与状态，可通过任务日历查看和调整个人安排。独立保留 PingCode 来源优先级和截止日期，插单后可重新安排，来源刷新不覆盖个人安排；单独修改状态不重置优先级，反之亦然。 |
| P03 | 功能、Bug 及管理协作可记录任务描述、阶段、状态、阻塞和跟进；复杂事项可拆解子任务，小任务不强制走完整流程。个人行动完成、执行核验及来源交付分别表达，不要求在任务详情录入预期结果或结果与验证。 |
| P04 | 平台提效和 AI 基建作为项目／专题管理，关联里程碑、行动和风险；区分环境部署、实际试用与效果，缺少证据时不默认提效目标达成。 |
| P05 | GitLab MR 同步与专项视图：在确认的内网项目及评审范围内主动／定时刷新，展示项目、编号、标题、作者、外部状态及链接；按本人评审进展筛选和跟进，不自动将已合并记为本人已评审。 |
| P06 | PingCode 拉取：在授权和确认范围内主动／定时获取任务，展示任务编号、原始页面及来源状态；所需字段和状态映射在接入前核实。 |
| P07 | 身份与关联：分别按 PingCode 工作项、GitLab MR 的来源身份更新去重；本地绑定保留已有安排，PingCode 与 MR 可关联但不合并，关联产线月周重点不产生来源副本。 |
| P08 | 同步边界与异常：来源信息和个人安排分开保存，两处独立记录同步结果及时效；断连、权限变化和数据缺失时保留本地内容，显示异常且不误判完成或删除。 |
| P09 | MR 版本与复查：区分外部状态、本人评审进展与已检查提交版本；新版本到达时提示复查，保留旧结论的适用版本，MR 结束或评审安排变化时检查遗留行动。 |
| P10 | PingCode 回写：支持确认范围内的状态更新和选定进展评论，字段清单及权限待验证；由本人提交或在明确授权的 AI 执行计划内提交，保留变更与结果，私人安排不自动回写。 |
| P11 | 同步与回写可靠性：支持定时拉取暂停／恢复、变更识别、冲突提示、写入结果核实及安全重试；不静默覆盖来源变更，不重复发表评论，不将结果不确定显示为成功。 |
| P12 | 行动清单按紧凑列表展示标题、任务描述、优先级、个人行动状态、计划日期及快捷操作，保留筛选、排序、详情和归档能力；窄屏内容可读且无横向溢出。 |
| P13 | 列表支持安排今日和个人状态切换；收件箱安排今日转待处理，其他未结束状态保留，结束任务先重开；等待与阻塞补齐必要信息，失败保留输入，快捷操作不得清除其他详情的未保存标记或覆盖较新数据。 |
| P14 | 列表提供永久删除，须二次确认；按第4.11节事务清除任务、操作历史和活引用，保留子任务及历史副本，不保留删除记录。修订冲突、失败或存在在途操作时不得误删；确认提示说明历史副本保留及恢复、同步、重新生成可能带回任务。 |
| P15 | 任务详情使用“任务描述”，不显示“项目 / 专题”“预期结果”“结果与验证”输入区域，兼容保留存量数据；保存成功立即关闭详情并刷新原视图，失败或修订冲突保留详情及输入，未保存离开时提供保护。 |

首版所有 P 编号均为核心范围。GitLab 同步、MR 专项视图、新提交识别与 PingCode 双向回写纳入首版；代码内容的实际评审继续在公司 GitLab 完成，不要求工作台成为代码评审编辑器或引入 AI 自动评审。

## 6. 管理需求

### 6.1 产线管理：管理侧重点

三个产线均有负责人，工作台帮助本人掌握重点与偏差，不接管负责人日常排程。首版由本人记录计划和反馈，不要求负责人增加账号或重复填写全部任务。

| 编号 | 需求 |
| --- | --- |
| M01 | 三产线总览与单产线详情，具体按 FR-19；名称、负责人可配置。 |
| M02 | 月重点登记、完成度与上月结转，具体按 FR-20。 |
| M03 | 周重点登记、按周查看、上周对比与遗留标识，具体按 FR-21。 |
| M04 | 进展更新、周期提醒与月末汇总，具体按 FR-21、FR-22；反馈来源、时间及协调行动继续保留。 |
| M05 | 调整与结转：保留原计划及调整原因，未完成任务可延续到下周／下月；新周期保存独立计划记录，原周期未完成事实不被覆盖。 |
| M06 | 风险登记与预警，具体按 FR-23、FR-24；风险转问题历史、关闭结果及依据继续保留。完成处置行动不自动关闭风险。 |

#### 6.1.1 产线月周重点需求

产线月周重点以 FR-19～FR-25 为详细需求，M 编号用于对应管理能力。

#### 6.1.2 数据和验收口径

- 时区 Asia/Shanghai，周一至周日为自然周，月重点归属其开始日期所在自然月；新建月／周重点使用完整自然月／周。跨月周可关联有交集的同产线月重点，旧自定义周期继续可读写。
- 描述沿用重点标题，月目标／周目标沿用预期结果，进展说明沿用实际进展；增加月完成度（0～100 整数）及备注。月状态与周进展分开：新月重点仅提供上述五种状态；历史等待状态兼容展示。新周进展显式记录四种状态，旧记录根据阶段状态兼容推导。更新时间由后台维护。
- 月完成率＝已完成月重点数／非取消月重点数，四舍五入到整数百分比；空月或全部取消显示“暂无有效重点”，不显示虚假 100%。单项完成度独立记录，已完成时为100%，其他状态不能以100%替代完成事实；不平均周进度。超过5条仅提示，不阻止登记。
- 上周对比并排显示前后两周，自动列出上周未完成且未取消的遗留项；以结转链识别承接关系，不按标题猜测。已结转仍保留上期未完成事实。结转重置实际进展和完成度，保留描述、目标、负责人、备注、任务关联与原因；同一来源重点到同一目标周期只生成一次，整批操作原子执行。
- 风险等级默认中，旧风险缺等级按中处理；旧风险缺目标闭环日期不据复查日期猜测。开放风险包含开放和跟踪中，已闭环不再预警；高等级或目标闭环日期早于今日且未闭环时飘红，目标当天不算超期。是否升级由本人维护，不自动对外通知。
- 站内提醒按产线配置周几（1～7，默认5），提醒日及之后若本周无重点或重点尚未在提醒日之后更新，提示更新；完成、取消项不催更。未初始化的当前周／月分别提示新建或结转。后台运行时每分钟检查周期，页面每分钟刷新；关闭期间不执行或推送，下次启动补算已结束月份。
- 月末当天展示实时汇总；自然月结束后保存每线每月独立汇总事件，按月末前的创建和状态历史计算，重复检查不重复保存。历史状态依据不足时标记不完整，不伪装准确历史。已存月末汇总不因次月修改而重写；月末汇总和新增字段纳入备份／恢复。
- 新建周回顾自动增加独立“产线进展”节，与个人任务简报及下周计划共存；包含各线该周重点完成数／总数、逐项状态及说明、受阻／有风险项、周期内风险新增／闭环事件。风险变化使用事件时间，不用当前更新时间代替。内容保存为可编辑事实快照，复制、Markdown导出、交付版本均保持创建时内容；后续变化提示差异，旧回顾不自动重写。
- 沿用递归隐私排除，人员／招聘及敏感关联不进入普通汇总和周报；修改后隐私检查仍阻止既有回顾导出。真实业务验收须由用户人工复核。

### 7.1 工作回顾规则

- **周期与选材：** 新建周回顾默认选中本周事项，新建月回顾默认选中本月事项；任务的计划、开始、截止、跟进或实际完成日期至少一项落入周期时默认勾选，包含开始与结束当天。仅新增、同步、编辑、重开或存在管理关联不触发任务预选；无日期或日期均在周期外的任务默认不选，允许手动补选。产线重点按同类型周期相交选取，风险与里程碑按周期内活动、计划检查日期或周期关联选取。关联任务独立满足日期条件，手动取消后不得隐式带回。
- **材料保护：** 已取消事项默认不选；人员、招聘、敏感内容及其关联按隐私规则排除。自动选材加载中、失败或选中事项不可见时禁止创建，保留输入并提示处理方式。修改周期时重新选择，旧请求结果不得覆盖新周期。
- **报告格式：** 事实草稿的本期事项从“1、”开始连续编号，每项一行，采用“1、任务标题--状态”。状态仅使用“完成、进行中、未完成”；正常完成直接写“完成”，进行中和未完成可附一句简短原因。原因仅使用已有事实或本人补充，不推测。完成表示事项的本地行动状态，外部交付与验证结果仍分别记录。
- **下周计划：** 新建回顾提供“下周计划”选项并默认勾选。下周为所选回顾结束日期所在周的下一自然周，范围为周一至周日，界面及报告显示具体日期；月回顾采用相同规则，仍使用“下周计划”。
- **计划选材：** 默认选中计划日期落在下周且未完成、未取消、未归档的事项，排除敏感关联；创建、开始、截止、跟进和实际完成日期均不代替计划日期。允许手动增减计划事项，也可取消下周计划选项。调整结束日期后重新选取计划；计划选材失败时可重试或关闭该选项后仅创建本期回顾。
- **计划编号：** 报告单列“下周计划（开始日期 — 结束日期）”，各项按“1、任务标题”“2、任务标题”连续编号，从1重新开始。计划不附本期完成状态，不计入本期成果。同一事项可分别出现在本期回顾和下周计划中，事实来源保持唯一。
- **保存与交付：** 本期事项及下周计划均可编辑，复制、Markdown 导出及交付版本使用已保存正文并保留编号。来源事实保留快照与追溯关系，后续变化提示差异；已保存的历史正文和交付版本不自动重写，历史章节式回顾继续可读写。

示例：

```text
本周回顾
1、接口联调--完成
2、问题修复--进行中，等待复测环境
3、资料整理--未完成，等待补充材料

下周计划（2026-11-09 — 2026-11-15）
1、完成问题复测
2、整理验收资料
```

### 7.2 补充边界

- 中心总结不能把本人的台账自动视为完整中心数据，需要收集的同事材料显式列出。
- 月总结不简单拼接周报；区分周阶段结果与月目标完成，保留结转和未完成情况。
- 人工补充无来源的材料标为待核对；AI 建议／总结为需复核草稿，执行结果另有真实回执和核验，不能将模型声称完成或缺少来源的内容自动记为事实。
- 普通汇报导出与完整备份分开；完整备份可能包含敏感信息，不应默认共享。
- 不将内部代码、患者数据、密钥、未脱敏日志或招聘隐私写入任务正文或发送至未经批准的服务。
- 部署、设备和数据规模未确定，性能目标与存储保护方案在技术设计阶段补齐，不把未测指标写成已满足。
