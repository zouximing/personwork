# 来源同步、受控回写与备份恢复

核对日期：2026-11-07。此说明记录实现边界与本机验证结果；没有访问公司 PingCode/GitLab，没有使用真实凭据、内部项目或公司数据。

## 来源协议

| 来源 | 当前实现 | 范围与认证 |
| --- | --- | --- |
| GitLab | REST API v4，GET `/user`、GET `/projects/{project_id}/merge_requests`、GET `/projects/{project_id}/issues` 及对应单个对象；全部写入被后端允许清单拒绝 | `PRIVATE-TOKEN` 个人访问令牌；配置数字用户 ID、逗号或换行分隔的数字项目 ID；分别以 `assignee_id` 拉取本人 Issue／MR、以 `reviewer_id` 拉取本人待审 MR，再核对 `assignees`／`reviewers` 并去重；不以作者判定本人职责 |
| PingCode | 公开 REST API v2，GET `/v2/myself`、GET `/v2/pjm/workitems`、GET 单个工作项、GET `/v2/comments`、POST `/v2/comments` | `Authorization: Bearer {个人访问令牌}`；配置实际用户 ID 与项目 ID；按 `assignee_id` 拉取本人负责的工作项，不提供 OAuth 换令牌或企业令牌登录流程 |

地址填写 API 所属根地址，GitLab 不要附加 `/api/v4`，PingCode 不要附加 `/v2`。GitLab 未关闭的 Issue／MR 使用 `state=opened` 拉取，不受历史天数限制；另以 `state=all` 与 `updated_after` 补充近期结束的事项，合并去重。PingCode 使用 `updated_between`，请求包含归档、删除标志范围；未知工作流状态保留原名。范围收窄、停用、断连和记录缺失均不删除缓存或自动完成个人行动。

PingCode 身份读取需要实际令牌具有个人信息读取能力；工作项和评论分别需要对应读取、写入权限。实际最小权限必须在部署实例验证。GitLab 令牌必须同时允许身份和所选项目 Issue、MR 读取，任一列表读取失败不会计作完整成功。连接测试只读取编辑中的设置，测试不保存、不试写，也不将读取通过当作写权限验收。

GitLab 按 `X-Next-Page` 顺序读取并检查可用的 `X-Total`；PingCode 使用从 0 开始的 `page_index`、`page_size`、`total`、`values`。不连续、重复、总数变化或已能识别的不完整分页不会推进最后完整成功时间。来源筛选中消失的已缓存对象会单独读取，无法读取则保留旧快照并报告部分失败。

GitLab 来源身份为实例、对象类型、项目与内部 ID，避免同编号／同内部 ID 的 Issue 与 MR 碰撞；同一 MR 同时指派与评审时共用一条来源记录、一个任务，两个职责分别记录。PingCode 来源身份为实例与工作项 ID，工作项换项目不会新建副本。当前 SHA、已检查 SHA、本人评审状态和原结论仅用于 MR。新 SHA 不清除旧结论，MR 合并不自动认定本人已评审。Issue 显示 `#编号`、MR 显示 `!编号`，均进入任务中心；Issue 不显示 MR 评审表单，也不接受登记评审。取消指派或评审职责时保留已有个人行动并提示核对。

旧 GitLab 来源记录缺少对象类型时按 MR 解释，旧 PingCode 按工作项解释；再次同步原地补齐字段，保留原 ID、任务绑定、已检查版本和评审结论。加密备份恢复采用相同身份规则，旧记录无需预先迁移。回顾事实保留来源类型，Issue 来源不附加 MR 的提交／评审状态，既有回顾版本继续保留原文。

来源与任务中心任务采用明确绑定；一个任务最多绑定一个来源对象，PingCode 与 GitLab 事项通过双向多对多本地关联表达关系。改绑时仅归档未被个人修改的导入空壳，已有个人计划保留。公开 API 依据于 2026-11-07 核对 GitLab 官方 Issues API（https://docs.gitlab.com/api/issues/）及 Merge requests API（https://docs.gitlab.com/api/merge_requests/）；公司部署版本、字段和实际权限仍须实接验收。

更换地址会产生新的实例 ID，不自动沿用旧凭据。凭据支持保留、更换、清除；输出、普通记录、备份与日志不包含访问凭据或其引用。读取不跟随重定向，避免认证请求被转投其他主机。配置变化或停用后，后续分页请求停止，旧请求结果不会写入新配置。

关闭服务调用幂等的 `await SourceService.close()`，先停调度并拒绝新的同步、提交和核实，再等待在途操作结束，之后才可关闭数据库。关闭期间不继续分页；已经发出的评论 POST 会等待有时限的响应并保存已取得的回执，后续读取核实被停止时保留 `uncertain`，不会重发评论。

## 回写边界

- 仅 PingCode 的状态和选定进展评论可以建立预览；私人备注、个人计划、排序及其他字段没有回写入口。
- 评论预览 `outboundValue` 展示实际发送的完整正文，包括可见唯一标记 `[个人工作台提交:请求UUID]`。提交前核对当前实例、地址、配置版本、项目范围、认证身份和对象身份。
- 同一请求 UUID 对应的不同内容被拒绝。提交状态在发请求前持久化；断连、超时或响应丢失保持 `uncertain`，禁止盲目重发。读取来源并唯一匹配完整评论与回执后才显示 `confirmed`。重启不补发旧提交。
- **状态更新尚未通过实例验收。** 公开 API 的 `state_id` 更新存在工作流约束，当前没有核实条件写或原子并发保护契约。先读后写无法关闭竞争窗口；当前版本会提示冲突或返回 `blocked`，不会发送未经保护的状态覆盖。此限制意味着 AC25/AC26 的真实状态回写验收仍未完成。
- 不兼容 v2、接口无权限、评论正文被实例转换而无法准确匹配、证书或网络异常，均不会被显示为真实接入成功。尚未验证公司实例的版本、域名、证书、代理、权限、字段与自定义工作流。

## 备份与恢复

完整导出采用口令派生密钥及 AES-256-GCM；本机保护快照通过已有 SecretVault 主密钥加密，Windows 主密钥使用当前账号 DPAPI 保护。普通汇报导出与完整备份的范围不同；完整备份可以包含私人管理行动，须单独保管口令和文件。

备份逐种校验任务、提示词、来源设置、来源对象、回写、产线、周期、风险、回顾、例行规则、里程碑、模型与执行记录，并检查引用、循环、周期关系、外部身份唯一和双向来源关联。异常格式、坏引用、重复身份、嵌入凭据字段或不兼容版本不会改变原数据库。恢复前先保存原库的本机保护副本，再在同一事务恢复记录与历史；同毫秒事件的原有顺序也保留。

恢复不会恢复外部执行授权：来源和模型停用、凭据引用清除、模型配置版本更新且能力恢复为未测试；AI 执行记录进入待核实；已发出的回写进入 `uncertain`，未发出的预览为 `blocked`。历史回执和产物记录保留，但不重新发出请求。旧备份未包含来源设置时，读取时补建两个停用的默认配置。

本机快照接口：

| API | 返回或输入 |
| --- | --- |
| GET `/api/backups/snapshots` | `{items:[{name,savedAt,bytes}]}`，文件名包括 `.protected` |
| POST `/api/backups/snapshots/:name/restore` | `{confirm:true}`；后端 `restoreProtected(name)` |

只允许应用的严格文件名；拒绝目录或文件符号链接，并通过打开的文件句柄复核身份。每小时刷新当日日快照，保留最近 7 份日快照；轮换前验证快照确由本机密钥认证，不删除损坏或无法识别的文件。恢复前副本不会自动轮换。外部备份和本机快照当前限制为 30 MiB，超过上限会明确失败，不生成无法恢复的文件。服务恢复路由应先获取维护锁，并拒绝与进行中的来源同步、提交、结果核实或 AI 执行交错。
