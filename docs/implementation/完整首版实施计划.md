## 工作边界

沿用技术方案，原型与需求输入不改。Windows 单机先运行；Linux部署支持在本地做配置/拒绝不安全配置检查，无真实Linux服务器时只标未实机验证。不存在真实内网地址/凭据，因此以真实本地HTTP测试服务器验证适配逻辑、用实际磁盘与浏览器验证产品；不将这些测试视为公司实例/模型真实接入验收。

## 实施单元与责任边界

1. 根工程、contracts/index、server/storage/workbench：主代理。真实 SQLite 迁移、事务、修订冲突、任务与提示词，先测试后实现。证据 tests/workbench.test.ts。
2. server/secrets/crypto/backup/config/app/index：主代理。DPAPI/Linux主密钥、备份认证加密、恢复校验、CSRF/Host/Origin/远程认证。证据 tests/protection.test.ts、tests/api.test.ts。
3. server/management、contracts/management：管理代理。产线月周、风险与问题、结转、周期总结、事实回顾与版本、专题。证据 tests/management.test.ts。
4. server/connectors/source-settings、contracts/sources：来源代理。PingCode v2和GitLab元信息、配置身份、分页、版本复查、调度、评论预览/核实，状态更新需来源侧原子并发能力满足后启用。证据 tests/sources.test.ts。
5. server/models、contracts/models：模型代理。三类配置、OpenAI兼容/Ollama原生、真实调用及能力检测、拆解与总结。证据 tests/models.test.ts。
6. server/executions、contracts/executions：主代理。单次计划授权、注册工具/参数/材料/输出目录白名单、预算、取消与中断恢复、实际文件产物与读取核验、限定PingCode动作。证据 tests/executions.test.ts。
7. web/src：前端代理。正式方案A全部入口、真实接口联动、未保存保护、失败保留输入、提示词复制、管理回顾与来源/模型/执行设置。证据 tests/e2e/workbench.spec.ts。
8. 主代理整合审查，运行npm run check与浏览器检查、独立进程重启、快照及部署脚本验证，输出README/需求追溯/验证记录。无需重复请求阶段开始许可。

## 当前裁定

- Ruling: 含默认值的Zod对象不能直接partial用于PATCH；去除默认值后optional — 已通过父子关联/备注/日期回归验证。
- Ruling: PingCode公开API不证明原子条件写，状态覆盖在能力未验证时阻止并显示原因；评论使用预览可见的操作标记和读取核实 — 保留真实实例未验收限制。
- Ruling: API后端默认无正文请求日志；外部错误只返回分类和可操作提示，不回传原始请求/响应秘密。
- Ruling: 任务、来源、验证、交付分开；AI文件核验仅证明产物存在和内容回读一致，不自动标记业务交付完成。
