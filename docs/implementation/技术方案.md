# 个人工作台技术方案

日期：2026-11-07。状态：已按追加授权推进完整首版本地实现；阶段结果、外部未验收项见《需求追溯》《验证记录》。

## 已确认决策

- 今日工作台采用需求v0.9 §3.3（TW-01～TW-09），实现细节见《今日工作台增量方案》。首页由`DashboardService`集中聚合现有任务、来源快照、产线重点与风险；沿用React/Fastify/SQLite及原有鉴权。

- 2026-11-07 用户追加确认：原“个人任务”入口统一为“任务中心”，涵盖原个人任务、其他管理事项及周期生成任务；管理看板移除“其他管理事项”页签，保留周期规则配置。任务列表及导航待办数量不再按 `category` 排除管理任务，已归档任务仍通过归档筛选查看，已完成／已取消任务不计入待办数量。沿用现有任务 ID、分类、状态、关联和历史，无数据迁移或复制；分类继续参与内部资料保护，人员／招聘隐私规则沿用既有实现。
- 需求基线为《个人工作台需求文档》v0.7，P01—P11、M01—M08、S01—S18 全部保留为首版范围。原型采用根目录最新方案 A，深墨绿侧栏，不采用 v2。
- 第一阶段：公司 Windows 工作电脑、单用户、本机浏览器和后台；无 VPN、代理或特殊公司证书。
- 第二阶段增加公司 Linux 服务器部署后台，Windows 浏览器访问。来源访问由后台所在机器发起，因此必须另外验证 Linux 到 PingCode、GitLab、本地模型的连通性。
- React/TypeScript/Vite + Node.js 24/Fastify + SQLite。单工程按业务拆分；不引入多人协作或公网暴露。
- 单机监听 loopback；远程模式必须显式绑定地址，配置准确 Origin，使用访问口令及 TLS，不能将访问口令明文通过内网 HTTP 传输。证书、反向代理及服务器由第二阶段实际部署验证。
- 凭据存储通过接口隔离：Windows DPAPI CurrentUser 包裹主密钥；Linux 使用单独提供、权限严格的主密钥文件。凭据内容再使用 AES-256-GCM 加密，数据库仅有引用。
- 默认数据目录：Windows LOCALAPPDATA/PersonalWorkbench；Linux XDG_DATA_HOME/personal-workbench（未设置时 ~/.local/share/personal-workbench）。实际目录在设置可查看。
- 业务数据与代码分开。暂不允许敏感人员/候选人正文持久保存，不将内部材料发送外部模型，不自动切换模型。当前无真实来源数据。
- 完整备份使用口令派生密钥和认证加密，包含任务、提示词、设置及历史，不包含凭据和主密钥；恢复后凭据需重录。备份口令由用户输入，不保存。恢复验证完成前不改变现有数据，恢复前保留原数据的保护副本。
- 默认每日后台检查创建本机保护快照，保留最近七日；仅后台运行时触发，不承诺电脑关闭时运行。手动可移植备份为独立入口，恢复口令须另存。未有异机副本前不能承诺抵御磁盘损坏。

## 2026-11-07 追加：周月回顾简报

用户确认新建回顾采用简洁清单：每项一行“1、任务标题--完成／进行中／未完成”，按最终去重事项顺序从1开始连续编号；正常完成不附原因，其他两类可补简短原因。周回顾默认周一至周日，月回顾切换为当前自然月；日期仍可手动修改。自动选材为独立只读接口 `/api/reviews/selections?kind=week|month&start=YYYY-MM-DD&end=YYYY-MM-DD`。

任务仅在计划／开始／截止／跟进日期或实际完成日期至少一项落入所选周期时默认勾选，含开始和结束当天；完成时间按 Asia/Shanghai 换算日期，旧记录只使用既有完成事件恢复的依据。新增、同步、重开、编辑及管理关联本身不触发任务勾选，无任务日期或全部日期在周期外的任务默认不选，仍允许手动补选。产线重点按同类型周期相交选取，风险／里程碑按本期活动、计划检查日期或选中周期关联选取；关联任务仍须独立满足日期条件，用户取消勾选后不再隐式带回。敏感类型及其关联继续由后台递归排除，取消事项默认不选。切换周期会重新选材，异步旧响应不能覆盖新周期；选材失败时禁止创建错误报告。

新记录写入 `format=brief` 和可编辑的 `reportBody`，复制、导出和发布使用已保存正文；完整事实和来源保留在折叠区。新简报不生成隐藏的六章节内容，报告过长时在写入前拒绝并提示减少材料。已有记录缺少 `format` 时按旧 `sections` 格式解释，读取不转换正文；已发布 Markdown 不重生成。两种格式均保留修订冲突、隐私检查和恢复校验。

简报状态取创建时的本地行动／管理状态，不代表外部来源已交付或验证通过；选择过去周期时不会倒推历史期末状态。`done/closed` 显示完成，`doing/waiting/watching` 显示进行中，其余显示未完成；已有阻塞或等待原因可带入，其余由用户补充。原因不会从私人备注或未来行动中推测。

## 2026-11-07 追加：历史回顾删除

回顾正文操作区提供“删除回顾”，草稿、交付过的回顾及旧章节式记录均适用。点击后显示独立确认弹窗，包含已保存标题、交付版本数量、删除范围与无法直接撤销的提示；当前有未保存修改时同时提示会丢弃这些修改。取消、关闭和 Escape 保留原输入，不发删除请求；提交期间禁用重复提交和关闭，失败后保留弹窗、错误及输入。

`DELETE /api/reviews/:id` 接收严格校验的 `{ revision, confirm: true }`。确认弹窗捕获打开时的记录修订号，后台在 SQLite 事务中校验记录存在及修订一致，按 kind、id、revision 删除整条回顾并追加 `review.deleted` 审计事件（仅记录交付版本数量）。删除包含该记录内的事实快照、独立 AI 草稿和全部交付版本；关联任务、产线计划及其他回顾保留。事件写入失败回滚删除，过期修订返回 409，记录不存在返回 404，继续复用 CSRF／Origin 保护。模型请求返回后的既有修订检查会拒绝向已删回顾回填草稿。

成功后从界面列表移除回顾，清空当前编辑器及未保存标记。保留审计事件和既有备份／导出副本，不清理真实数据目录或快照；恢复删除前备份可能重新带回该回顾，因此这里不表示安全擦除或回收站。

## 2026-11-07 追加：下周计划

新建周／月回顾默认勾选“下周计划”，显示回顾结束日期所在周的下一自然周（周一至周日）的具体日期。月回顾沿用下周计划，不切换为下月。自动选取仅依据任务 `planDate`，不依据创建、截止或跟进日期；已完成、取消、归档和递归敏感关联排除。允许手动增减事项或关闭计划。独立异步加载有取消保护，周期变更不会被旧响应覆盖；计划选材失败或返回不可见事项时禁止创建，可关闭计划继续仅生成回顾。

`reviewRangeSchema` 增加 `purpose=plan` 的任务选材；回顾保存 `includeNextWeekPlan` 和 `nextWeekTaskIds`。旧请求／数据默认不启用计划，新界面显式提交默认开启。两部分分别按1、2、编号，未来计划仅写标题。本期和计划共用唯一事实快照，角色由本期 selections 与计划IDs区分；复制、导出、交付版本保存完整正文。模型收到本期事实IDs及下周计划范围与IDs，明确禁止把未来计划写成本期成果。全文长度检查在写入前执行；旧草稿和交付版本不自动重写。

备份同时校验草稿和交付版本计划IDs在各自事实快照中存在。当前计划选择是实时关联，删除任务时随关联清理；交付版本保留原计划IDs与事实，允许对应任务已删除，继续可备份和恢复。隐私禁导出沿用事实检查及删除功能的隐私保护。

回顾正文、事实及全部已发布版本保持原样；版本下周任务标识按历史事实引用校验，当前选择仍严格检查活任务存在性。普通任务删除后历史回顾仍可复制导出；删除时已私密的任务为关联回顾固化保护标志，禁止借删除解除隐私限制。存活子任务及管理／来源关联通过服务端只读 `privacyRestricted`、`internalContext` 保留原上下文约束，普通 PATCH 无法清除；来源重新同步或再次绑定时继续保护存活内容。

删除不修改历史备份、保护快照、已导出文件或已有执行产物，不表示介质安全擦除。恢复旧备份、来源再次同步或显式重新生成周期任务均可能重新带回内容。测试使用独立数据目录与后台，用户现有后台需沿用原环境变量和实际数据目录重启后加载新版本。

## 必须实测的边界
