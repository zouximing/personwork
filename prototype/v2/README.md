# 序 · 个人工作台 / 需求文档2原型

依据 [个人工作台需求文档2](../../docs/个人工作台需求文档2.md)，只制作 **两种 UI 方案**。这是用于讨论信息结构与操作路径的临时原型，所有任务、人员、产线和 MR 数据均为虚构。

设计问题：**软件研发管理者的首页，应先回答“今天做什么”，还是先回答“三条产线哪里需要我介入”？**

## 打开

可以直接双击本目录的 `index.html`，无需安装依赖。也可在项目根目录运行现有静态服务器：

```powershell
python prototype/serve.py --port 8766
```

浏览器访问：

- A · 今日行动台：`http://127.0.0.1:8766/v2/?variant=A`
- B · 产线指挥台：`http://127.0.0.1:8766/v2/?variant=B`

服务器只监听 `127.0.0.1`。前台运行时按 `Ctrl+C` 停止；如果端口被占用，可更换 `--port`。本次预览会话使用后台 Python 进程，停止预览可在确认命令行与端口对应后结束该进程。

使用底部浮动条或键盘左右箭头切换方案；`N` 快速记录，`/` 搜索。输入框、选择框、可编辑内容和打开的对话框不会被全局快捷键打断。底部 `ⓘ` 显示当前布局、页面、任务和风险计数及最近操作。

URL 的 `view` 参数支持 `today`、`tasks`、`lines`、`mr`、`report`、`people`；两种方案可访问相同页面。

## 两种方案的取舍

| | A · 今日行动台 | B · 产线指挥台 |
| --- | --- | --- |
| 主问题 | 今天最值得投入精力的三件事是什么？ | 三条产线的重点推进到哪里，哪里需要介入？ |
| 结构 | 固定左侧导航；主栏个人行动，右栏等待、MR 与日程 | 顶部导航；总体摘要、三条产线并列，右侧个人行动与等待 |
| 第一优先级 | 今日三件要事 | 周重点完成情况与异常 |
| 视觉 | 浅色、低饱和绿，节奏相对舒缓 | 深蓝顶栏、紧凑信息区，便于并排比较 |
| 取舍 | 产线完整摘要较靠下，管理信息需要更多滚动 | 个体任务退到侧栏，研发执行信息相对收敛 |
| 更适合 | 每日开工与个人推进 | 产线周例会与跨线协调 |

建议先以 A 评审日常开工体验，再用 B 检查管理场景。**这只是设计建议，尚待用户选择，不是已验证的使用结论。** 两种方案可组合取长；本次没有生成第三种方案。

演示日期固定为 **2026年11月6日（周五）**，周范围为 **11月2日至11月8日**，月为 **2026年11月**。这不是系统当前日期；超期与周期统计均按该演示日期计算。

## 建议体验路径

1. 在首页完成一件要事，切换方案，确认状态共享。到任务中心用 ☆ 替换要事；最多三件，完成后自动移出。
2. 按 `N`，只填一句话进入收件箱。打开任务，编辑工作域、状态、日期与重要/紧急属性。
3. 将任务转成“等待他人”，填写等待对象、内容与预期回复日期。三个字段必填；超期等待会出现在首页与提醒中。
4. 在任务中心按工作域、状态筛选，搜索标题、描述、备注，切换列表、状态看板与四象限。
5. 进入 MR 评审，按项目筛选、查看分支与停留时长。点击“记录评审完成”，生成一条 D2 已完成事项；来源仍显示虚构的 Open 快照，不发送 GitLab 请求。
6. 在产线重点切换月/周重点，更新状态和进展说明。月重点完成率按 **已完成条目数 / 全部条目数** 计算，单条目完成度另行显示。
7. 完成一个受阻周重点后，查看关联风险：风险不会自动关闭。打开风险填写依据，再独立更新状态。
8. 生成周/月总结素材，人工修改、复制或下载 Markdown。产线进展独立成节，包含受阻/有风险项及有日期记录的风险新增/闭环变化。人员与招聘记录默认排除。

## 需求覆盖与原型边界

| 需求 | 本次可以讨论和体验的内容 | 未实现的正式能力 |
| --- | --- | --- |
| FR-01～06、FR-10、FR-12 | 统一任务、快速捕获、状态和委派、四象限、每日要事、搜索筛选 | 完整字段配置、严格状态规则与持久化 |
| FR-07～09 | 周期任务实例、应用内提醒汇总、已完成默认隐藏 | 自动周期生成、后台与 Windows 通知、正式归档机制 |
| FR-11、FR-13～15 | 固定周/月演示周期、完成记录统计、总结素材编辑与导出 | 耗时统计、自定义时间范围和模板、独立素材库 |
| FR-16～18 | MR 虚构快照、项目筛选、超过 2 天提示、本地评审完成记录 | GitLab 连接、定时同步、真实源链接和评审行为 |
| FR-19～25 | 三线月/周重点、目标与负责人、进展更新、风险与独立闭环、进入周报 | 历史周对比、真实结转、周期初始化、提醒调度、完整风险审计 |
| FR-26～28 | 虚构人员沟通与招聘阶段示意、关联任务入口 | 完整候选人流转、HR 集成、面试提醒和人员历史数据库 |
| FR-29～34、NFR | 本地静态预览、Markdown 导出、明确数据边界 | 真实 AI、数据库、登录鉴权、备份恢复、整体导入导出和审计 |

该原型没有应用后端，没有数据库、本地存储或第三方网络业务请求。所有修改仅在当前页面内存中存在，刷新重置。复制和下载是用户主动触发的本机操作。剪贴板不可用时选中正文，提示手动复制。

不采集口令或 Token，不使用真实内部资料；不能以此认定需求中的数据安全、性能、正式集成或业务验收已完成。

## 文件与交接

- `index.html`：独立预览入口。
- `styles.css`：A/B 两种页面结构与样式。
- `app.js`：虚构数据与共享的内存交互。
- `screenshots/`：两方案首页、主要子页面、窄屏与任务抽屉截图，以及一次实际下载的演示 Markdown。
- `verification-results.json`：浏览器检查逐项结果。
- `verification.md`：验证命令、结果、范围及限制。

旧 `prototype/` 下的三方案原型与原需求文档未修改。新增内容均在 `prototype/v2/`。当前工作区不是 Git 仓库，因此没有初始化仓库、创建分支、提交或发布。

状态：两种交互方案已交付，**待用户比较布局与操作路径**。正式开发应依据选定的设计重新实现，并补齐存储、鉴权、真实集成与正式验证；本原型不直接升级为生产应用。
